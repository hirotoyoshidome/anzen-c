# C言語コードレビュー用チェックリスト

レビューでは、細かな好みよりも安全性、所有権、エラー処理、保守性を優先して確認します。

## 基本

- [ ] 対象プロジェクトのC標準、コンパイラ、ツールチェーンに合っている。
- [ ] ESP-IDFを使う場合、ESP-IDFの設定とターゲット環境に合っている。
- [ ] コンパイラ警告を放置していない。
- [ ] 関数、型、変数の名前から役割が分かる。
- [ ] 公開APIと内部実装が分かれている。
- [ ] ソースファイルを `#include` していない。
- [ ] ヘッダファイルにインクルードガードがある。

## 型と境界

- [ ] 配列の添字、要素数、容量、メモリサイズに `size_t` を使っている。
- [ ] 符号付き整数と符号なし整数の比較や変換が安全である。
- [ ] ビット演算では意図したunsigned型を使っている。
- [ ] 固定長配列を初期化している。
- [ ] 配列外アクセスが起きない。
- [ ] 文字列領域にNUL文字分の余裕がある。

## ポインタとメモリ

- [ ] ポインタ引数に必要な `NULL` チェックがある。
- [ ] `malloc`、`calloc`、`realloc` の戻り値を確認している。
- [ ] `realloc` を一時変数で受けている。
- [ ] 動的メモリの所有者が明確である。
- [ ] 呼び出し側が `free` する必要がある場合、公開ヘッダやコメントで説明している。
- [ ] `free` 後のポインタを再利用していない。
- [ ] 呼び出し元のポインタを `free` 後に `NULL` にしている。
- [ ] 関数内の自動変数のアドレスを返していない。

## 関数設計

- [ ] 関数の責務が大きすぎない。
- [ ] 戻り値の意味が明確である。
- [ ] 成功と失敗の扱いが一貫している。
- [ ] エラー時に確保済みリソースを解放している。
- [ ] 引数を変更しない関数では `const` を付けている。
- [ ] ファイル内だけで使う関数に `static` を付けている。

## 抽象化設計

- [ ] 抽象化が必要な理由が、重複削減または安全な制約として説明できる。
- [ ] 似たコードが並列に増える領域では、インターフェイス固定を検討している。
- [ ] 過剰な抽象化や未使用の拡張点を作っていない。
- [ ] カプセル化により、内部状態を直接変更できない構造になっている。
- [ ] ポリモーフィズムを使う場合、関数ポインタのシグネチャと呼び出し責務が明確である。
- [ ] 所有権、初期化、破棄、エラー処理がインターフェイスで守られている。

## 文字列

- [ ] 文字列長とバッファ容量を混同していない。
- [ ] バッファサイズを関数に渡している。
- [ ] マルチバイト文字列を不用意に1バイト単位で文字処理していない。
- [ ] `wchar_t` をUTF-16固定として扱っていない。

## 構造体

- [ ] ポインタメンバの所有権が明確である。
- [ ] 初期化関数と破棄関数が必要に応じて対になっている。
- [ ] 動的配列では要素数と容量を分けて管理している。
- [ ] フレキシブル配列メンバを使う場合、確保サイズの計算が正しい。

## エラー処理とログ

- [ ] ファイル操作、システムコール、POSIX APIの戻り値を確認している。
- [ ] `errno` を使う場合、参照タイミングが適切である。
- [ ] エラーを握りつぶしていない。
- [ ] ライブラリコードが標準出力へ無条件にログを出していない。
- [ ] 必要な障害調査情報がログまたは戻り値から得られる。

## 並行処理

- [ ] 共有データへのアクセスに同期方針がある。
- [ ] スレッドセーフでない関数や状態を明記している。
- [ ] `_Atomic`、ミューテックス、条件変数などの使い分けが妥当である。
- [ ] FreeRTOSタスク間で共有するデータの所有権と同期手段が明確である。
- [ ] ISRから呼ぶ処理が、割り込みコンテキストで利用可能なAPIだけを使っている。
- [ ] POSIXのプロセス間通信では不要なファイルディスクリプタを閉じている。

## 組み込み環境とESP-IDF

- [ ] 動的メモリ使用の必要性と失敗時の動作を検討している。
- [ ] 大きな自動変数を置かず、スタック使用量を意識している。
- [ ] ヒープ使用量と断片化の影響を検討している。
- [ ] ログ出力の頻度、サイズ、タイミングが妥当である。
- [ ] ESP-IDF APIの初期化順序と呼び出し可能なコンテキストを確認している。
- [ ] ターゲット依存処理を上位ロジックから分離している。

## テスト

- [ ] 正常系のテストがある。
- [ ] 不正な引数のテストがある。
- [ ] メモリ確保失敗時の扱いを検討している。
- [ ] 境界値のテストがある。
- [ ] 可変長配列や再確保を伴う処理のテストがある。
- [ ] メモリリークや不正アクセスを検出する確認を行っている。
